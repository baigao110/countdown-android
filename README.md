# 倒计时（Android 版）

一款轻量、无广告、纯原生 Kotlin 编写的 Android 倒计时工具。
添加好倒计时后可在主界面查看，也能让它悬浮在其它应用之上，随时瞄一眼还剩多久。

---

## 功能特性

### 倒计时管理

- **自由添加 / 编辑 / 删除**：标题、目标日期时间、备注，全部可改
- **8 种显示模式**（点卡片上的「模式」按钮循环切换，模式恒定输出所选单位，不会随剩余量自动变格式）：

  | 模式 | 示例 |
  |---|---|
  | 标准模式 | 3周5天08:20:15 |
  | 小时模式 | 605时 |
  | 分钟模式 | 36320分 |
  | 秒模式 | 2179215秒 |
  | 天数模式 | 25天 |
  | 时分秒模式 | 08:20:15 |
  | 天时分秒模式 | 25天08:20:15 |
  | 天时分模式 | 25天08:20 |

- **8 种跳秒动画**（点「动画」按钮循环切换）：无动画 / 缩放 / 蒸发 / 坠落 / 像素化 / 碎片化 / 燃烧 / 震撼
  — 动画只作用在**末位数字**上，且只在数字真的变化时才播放
- **每个倒计时独立提示音**：点卡片上的提示音名称即可打开系统铃声选择器
- **主题颜色**：可为每条倒计时单独指定
- **长按拖动排序**，松手即保存
- **左滑卡片**露出「编辑 / 提示音 / 删除」操作

### 悬浮窗

- 逐条控制在悬浮窗中显示 / 隐藏
- 可拖动位置、点标题栏收缩成小条、调节不透明度（20%~100%）
- 走秒**整秒同步**：所有倒计时共用同一时刻基准，在同一瞬间一起跳秒
- 已知限制：系统「设置」界面处于前台时悬浮窗会被系统临时隐藏（Android 安全机制），返回后自动恢复；
  若任意界面都不显示，请在系统设置中开启「显示在其他应用上层」，并在品牌权限管理中开启「后台弹出界面」

### 每日吃药提醒

- 默认**每天 09:00** 弹一条系统通知，通知上直接点「**已吃药**」即记录当天
- 提醒时间随时可改：「关于」页点「**提醒时间**」，选一个时刻即可
- 「关于」页点「**吃药提醒：已开启 / 已关闭**」可一键关闭该功能；关掉后不再提醒，已记录的日期仍然保留
- **吃药日历**：按月查看哪天吃了、哪天没吃 —— 青色实心＝已吃药，淡红＝漏了，青色描边＝今天，未来日期不可记录
  - 顶部 ‹ › 切换月份，底部按钮一键记录 / 撤销今天
  - 点过去或今天的格子可补记或撤销
- **退出 / 关闭应用后照样提醒**（四重保障）：
  - ① 系统闹钟（setAlarmClock）：优先级最高，能穿透省电（Doze）策略，且不需要精确闹钟权限
  - ② 精确闹钟（setExactAndAllowWhileIdle）：与 ① 同一时刻再挂一路，Doze 的维护窗口里也能被唤起
  - ③ 每日重复闹钟：系统或 ROM 把主路清掉时兜底，提前 / 延后触发都不会重复打扰
  - ④ 到点后 **2 分钟、30 分钟各补响一次**：主路被系统推迟或清掉时兜住
  - ⑤ 后台巡检（JobScheduler，15 分钟一趟、重启自动恢复，另有第二个入口）：发现闹钟没了就补挂；发现今天该提醒的时刻已过却没响过就**补发**一条通知（标题标注「补发提醒」）
- **下次提醒时间也能改**：「关于」点「**下次提醒**」（按钮上直接显示当前时间），
  可指定具体的年 / 月 / 日 + 时刻 —— 比如今天错过 09:00，就把这一次改到今晚 20:30；
  改的只是即将到来的那一次，响过之后自动恢复每天固定时刻，也可在框里一键「恢复常规」
  手动改的那一次**一定会提醒**（不受「同一天只提醒一次 / 已记已吃药」的去重影响）
- 同一天只会提醒一次；已经点过「已吃药」的那天不再打扰
- **改完「下次提醒」会弹出引导**，可一键去「允许后台运行」（关电池优化）；回到前台也会立刻补发漏掉的提醒
- 收不到时先看「关于」页的「**后台自检**」：会列出下次提醒时间、闹钟挂载时间、**上次真正发出提醒的时刻**、
  通知权限、精确闹钟权限与电池优化状态 —— 据此能分清是「压根没发」还是「发了被系统拦下」

### 内置倒计时

自带五个：**当日倒计时、每周倒计时、当月倒计时、华都云境悦府（2026-10-31 00:00:00）、GTA6（2026-11-19 08:00:00）**

- 滚动型（当日 / 每周 / 当月）每天、每周、每月自动重算目标时间；固定型到期后停在 0，不会自动滚到下一周期
- 每周倒计时的目标为「下周一 00:00:00」，即本周结束的那一刻（以周一为一周的第一天）
- 内置项**可以删除、可以修改**；一旦改了目标时间就降级为普通倒计时
- 删除时会保存一份**设置快照**，之后在「＋」菜单里点「恢复内置」找回时，
  会一并还原删除前的主题颜色、显示模式、跳秒动画、提示音、悬浮窗设置与备注，只重新计算目标时间
- 四个内置项都在列表里时，「恢复内置」菜单项自动隐藏

### 更新与通知

- 打开 App 自动检查 GitHub 最新版本，发现新版本弹出更新提示，「立即更新」即在 App 内下载并拉起安装
  - 更新提示是**一个独立页面**（透明底 + 与对话框同款的玻璃卡片），不是系统对话框：
    「跳过开屏广告 / 弹窗拦截 / 广告过滤」这类工具盯的是对话框窗口，会把更新提示当成广告自动关掉；
    换成普通页面并延后 800 毫秒再拉起，就不会被误伤了；下载进度也直接显示在同一张卡片上
- 后台双路检查：JobScheduler（有网才跑，15 分钟一趟，重启自动恢复）+ AlarmManager 兜底（2 小时，失败 30 分钟重试）
- 「关于」页提供**通知自检**三入口：开启通知 / 测试通知 / 允许后台运行（关闭电池优化），并显示后台检查状态

### 通知收不到怎么办

退出 / 关闭应用后收不到通知（吃药提醒、版本更新通知都在此列），绝大多数不是提醒没安排上，
而是**通知在最后一步被系统拦下了** —— 权限没给、通知渠道被降级、后台被限制，
这三种情况的表现完全一样：代码照常执行、不报错、什么都不显示。

所以先在「关于」页点「**通知体检**」，它会把闸门一项项查出来，不合格的项下面直接给一个跳转按钮：

| 检查项 | 断了会怎样 |
| --- | --- |
| ① 系统通知总开关 | 任何通知都不会显示 |
| ② 通知权限（Android 13+） | 发通知被直接跳过，连日志都没有 |
| ③ 吃药提醒渠道 | 被收进「无声通知」或被关闭，静默丢弃 |
| ④ 版本更新渠道 | 同上 |
| ⑤ 精确闹钟 | 到点可能偏（已有系统闹钟 + 重复闹钟 + 巡检兜底） |
| ⑥ 电池优化 | 后台被冻结，到点没人去发通知 |
| ⑦ 后台活动限制 | 后台几乎跑不起来 |

应用侧为此做的加固：

- **通知渠道换新并提到最高级**（免打扰也会响、锁屏可见）；渠道重要性一旦定下来系统就不允许就地修改，
  所以渠道若被关掉会**自动删掉重建**，不再是无解死局
- **吃药提醒带全屏提醒**：息屏 / 锁屏时直接把吃药页弹到眼前
- **更多时机自动重挂**：开机、覆盖安装（升级后闹钟会被清掉）、解锁、改时间、改时区、跨天
- 进入应用时若发现通知被挡住，会**自动提示一次**（一天最多一次，累计最多三次）

## 界面说明

| 位置 | 操作 |
|---|---|
| 主界面列表 | 每条卡片：标题、目标时间、剩余时间、按钮行（显示 → 模式 → 动画 → 提示音名称） |

| 关于页·吃药提醒 | 开关（开启 / 关闭）· 提醒时间（每天）· 下次提醒（单次）· 吃药日历 · 测试提醒 · 后台自检 |

## 编译

需要 JDK 17 + Gradle 8.2 + Android SDK 34（本仓库不含 Gradle Wrapper，使用本机工具链）。

```bat
cd CountdownAndroid
build_apk.bat
```

产物：`countdown-android-v1.0.0.x-release.apk`（已 zipalign + 用 `countdown-release.jks` 签名）。

> 注意：项目路径若含中文，需要保留 `gradle.properties` 中的 `android.overridePathCheck=true`。

## 发版清单

1. `app/build.gradle`：`versionCode` +1、`versionName`
2. `UpdateManager.kt`：`CURRENT_VERSION_NAME` 与 `CHANGELOG` 头部追加一条
3. `update.json`：versionCode / versionName / date / apkUrl / htmlUrl / note
4. `build_apk.bat`：同步旧版本号
5. 编译 → 抽查 APK → 同步 GitHub → 回读核验

版本号支持四段，`versionToNumber = major*1e6 + minor*1e4 + patch*100 + build`；
**versionCode 必须递增**，发布后确认 `/releases/latest` 指向新版。
